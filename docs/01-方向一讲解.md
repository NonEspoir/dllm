# 方向一讲解：SFT + RL 的流程与技术点

> 写于 2026-10-29。配套文档：[题目.md](题目.md)、[00-任务分析.md](00-任务分析.md)。
> 建议阅读顺序：先吃透 §1.2–1.4（模型怎么生成）和 §3.2–3.3（为什么 log π 算不出来、轨迹法怎么绕过去），其余部分都在这两块的基础上展开。

---

## 0. 一句话概括

拿一个已经会"读题 → 写 Python 函数"的扩散语言模型 MDLM（GSM8K 准确率 18%），分三步：

1. **SFT**：用标准答案再教一遍；
2. **RL**：让它自己做题，按代码运行结果的对错来奖惩；
3. **对比**：在同一套考试上比较原始、SFT 后、RL 后三个版本，并解释为什么变好或变差。

## 1. 先搞懂模型

### 1.1 任务长什么样

一条真实的 TinyGSM 样本（TinyGSM 论文 Figure 2）：

```python
# 输入（题目）
In preparation for her party, Sarah buys 10 trays of food and 8 cases of beverages.
Each tray costs $50 and each case of beverages costs $20. What is the total cost ...?

# 输出（模型要写的）
def simple_math_problem() -> int:
    """
    In preparation for her party, Sarah buys 10 trays ...   ← 先把题目抄一遍
    """
    trays = 10
    tray_cost = 50
    cases = 8
    case_cost = 20
    tray_total = trays * tray_cost
    case_total = cases * case_cost
    total_cost = tray_total + case_total
    result = total_cost
    return result
```

**评测方式**：执行生成的代码，调用 `simple_math_problem()`，返回值等于 GSM8K 的标准答案就算对。所以模型不用自己做算术，只需要把题目正确地"翻译"成代码。

有两点要注意：
- docstring 里抄题目这部分占了不少输出，但基本是照抄，很容易。真正决定对错的，是后面几行里的**数字、运算符和变量引用**。
- TinyGSM 的 1185 万条代码是 GPT-3.5 生成的。作者只过滤掉了不能执行的代码，**没有验证答案对错**（题目是合成的，本来就没有标准答案）。也就是说，模型预训练时学过一些错误的解法。不过这不是 MDLM 只有 18% 的主要原因：同一份数据上 AR 模型能做到 54–63%，详见 [00-任务分析.md](00-任务分析.md) §1.4。

### 1.2 MDLM 怎么生成：先全部"涂黑"，再一轮轮"揭开"

GPT 这类自回归（AR）模型从左往右，每步写 1 个 token。MDLM 完全不同：

```
画布长 512：题目部分固定，后面全部是 [M]（mask，即"涂黑"）

第 0 轮: [题目] [M]  [M]  [M]   [M]   [M] [M] [M] ... [M]
第 1 轮: [题目] [M]  [M]  trays [M]   [M] [M] [M] ... [M]
第 2 轮: [题目] def  [M]  trays [M]   10  [M] [M] ... [PAD]
  ...
第 K 轮: [题目] def simple_math_problem ... return result [EOS] [PAD] [PAD] ...
```

每一轮做三件事：
1. 模型**同时看整张画布**（双向注意力，不只看左边），给每个 [M] 位置输出一个词表上的概率分布；
2. 每个 [M] 位置抛一次硬币，决定这一轮揭不揭开。揭开的概率由噪声调度决定，**和模型参数无关**；
3. 被揭开的位置，从模型给出的分布里采样一个词填进去。**填上之后就不再改**。

K 轮之后画布全部揭开。代码写多长不需要事先决定：模型会在合适的位置填 [EOS]，之后全填 [PAD]。训练时 pad 位置也算 loss，就是为了让模型学会这一点。

### 1.3 它是怎么训练出来的：遮盖比例随机的"完形填空"

对每条（题目，代码）：
1. 随机抽一个 t ∈ (0, 1)；
2. 代码部分的每个 token 以概率 t 换成 [M]，题目不动；
3. 让模型猜被遮住的原词，计算交叉熵；
4. 交叉熵乘以权重 1/t。

**和 BERT 的区别**：BERT 固定遮 15%，MDLM 的遮盖比例覆盖 0% 到 100%。遮 100% 就相当于"从零开始写"，所以 MDLM 能生成，BERT 不能。

**权重 1/t 的作用**：遮盖比例为 t 时，平均遮住 t×L 个词，乘 1/t 相当于按遮盖数量取平均。这个权重是推导出来的：加上它之后，loss 恰好是负对数似然的上界（ELBO）。所以 MDLM 是一个严格的概率模型，而不只是一个启发式的去噪器。

### 1.4 两个旋钮：步数 K 和温度 T

**步数 K**：生成区大约 400–450 个位置。
- K = 1024 时，每轮平均只揭开约 0.4 个，接近一个一个写；
- K = 64 时，每轮揭开约 7 个。

问题在于：**同一轮揭开的几个词是各自独立采样的，彼此看不见**。比如两个相邻位置同时揭开，可能一个填了 `tray_cost`，另一个填了和它接不上的词。所以步数越少速度越快，但质量越差。

**温度 T**：把 logits 除以 T 再做 softmax。T < 1 会让分布更尖，更倾向于选概率最高的词。

**为什么 T 从 1 降到 0.1，准确率能从 18% 涨到 33%？** 这是错误累积造成的。一个程序里有几十个关键 token，任何一个采错，整个程序就错。

> 示意：假设每个关键 token 有 2% 的概率被采错，50 个关键 token 全部正确的概率是 0.98^50 ≈ 36%。降温把这 2% 压下去，整体正确率就会大涨。

这说明：**模型其实"知道"正确的词概率最高，只是按原温度采样时经常手滑。** 这正是 RL 能发挥作用的地方：RL 会把概率集中到"能导致做对"的选择上。

## 2. 整体流程：五个阶段

| 阶段 | 输入 | 做什么 | 输出 |
|---|---|---|---|
| 0 复现 | 官方 MDLM checkpoint + GSM8K test | 跑官方评测，确认能得到约 18% | 可信的评测流程 + base 成绩 |
| 1 数据 | GSM8K train 7473 题 | 切出 6973 题训练集 + 500 题 dev 集；test 不碰 | 三份数据 |
| 2 SFT | base + 训练集里的（题目，正确代码） | 用和预训练相同的 loss 继续训练 | SFT 模型 |
| 3 RL | SFT 模型 + 训练集的题目和答案 | 模型自己做题、执行打分、强化 | RL 模型 |
| 4 对比 | 三个模型 + test | 统一设置评测，做分析 | 结果表、曲线、结论 |

**为什么阶段 0 必须最先做**：后面的所有结论都靠评测这把"尺子"。如果尺子不准，比如加载错了权重，或者从生成文本里抽代码的逻辑有 bug，后面全部白做。

**为什么数据要分三份**：
- **训练集**：给模型学；
- **dev 集**：用来调超参、选 checkpoint。"选第几步的 checkpoint 最好"本身就是在用数据做决策；
- **test 集**：只在最后用一次。如果拿 test 调参，test 分数就会虚高。题目明确要求了这一点。

**dev 集具体防的是什么**（10-30 补充）：
- 项目里有很多"挑选"：SFT 训几个 epoch、RL 学习率取多少、用 RL 第几步的 checkpoint、评测用多少步、温度取多少。每次挑选，都是"看哪个分数高就选哪个"。
- 每次评测都带随机误差（1319 题在 20% 附近约 ±1.1pp 的标准误）。挑最高分时，会连带挑中"运气好"的那一次，所以被挑中的分数系统性偏高。
- 模拟：10 个**真实水平完全相同**的 checkpoint，各在 test 上评一次，挑最高的报告，平均会虚高约 1.7pp；20 个约虚高 2.1pp。而 SFT 带来的提升可能也就几个 pp。
- 所以挑选全在 dev 上做，挑完之后用 test 只测一次，test 上的分数就没有被挑选污染。
- 也不能用训练集做挑选：模型在那些题上训练过，分数会因"背题"而虚高，看不出过拟合。
- 类比：训练集是课本习题，dev 是模拟考，test 是期末考。

**SFT 的要点**：
- 对 MDLM 来说，SFT 就是**换数据、不换 loss**：还是 §1.3 的完形填空，只遮代码部分。
- **数据从哪来**：GSM8K 原本的答案是自然语言解答，不是代码。有两种办法：
  1. 让 DeepSeek 把每道题写成 TinyGSM 格式的代码，执行一遍，答案对的才保留；
  2. 让 MDLM 自己每题写 8–16 份，执行后保留做对的。这叫 RFT（拒绝采样微调）。
- **可能的收益**：数据分布更贴近 GSM8K；数据经过执行验证，比 TinyGSM 干净。
- **主要风险**：只有 7k 条数据，170M 的模型训几个 epoch 就能背下来，所以要盯着 dev 分数及时停。
- **预期**：提升可能不大，因为模型已经在 1185 万条类似数据上训过。如果真的提升不大，原因本身就是报告里要解释的结论。

## 3. RL 细讲（技术核心）

### 3.1 一轮 RL 在做什么

```
重复几百次：
  ① 抽 16 道训练题
  ② 每题让当前模型写 8 份代码（rollout；用 T=1 保证答案有多样性）
  ③ 执行每份代码：答案对得 1 分，错得 0 分（reward）
  ④ 同一题内部比较：优势 A = 本份得分 − 这题 8 份的平均分
  ⑤ 更新模型：提高 A>0 的写法的概率，降低 A<0 的写法的概率
```

**第 ④ 步举例**：某题 8 份答案里有 2 份对，平均分 0.25。对的那 2 份 A = +0.75，错的 6 份 A = −0.25。

如果 8 份全对或全错，A 全部为 0，这道题就提供不了任何学习信号。所以太难和太简单的题都没用。base 模型准确率 18%，意味着有很多题"有时对、有时错"，这反而是 RL 很好的起点。

这就是 **GRPO** 的核心思想：不需要额外训练一个价值网络（critic），而是让同一道题的多份答案互相当参照。

**第 ⑤ 步的数学形式（策略梯度）**：

```
梯度 ≈ Σ_i  A_i · ∇ log π_θ(y_i | x)
```

意思是：朝着"让好答案的概率变大"的方向更新参数。这里的关键量是 **log π_θ(y | x)，也就是模型生成这份答案的对数概率**。

### 3.2 卡点：MDLM 算不出 log π(y|x)

- **AR 模型**：π(y|x) = p(y₁|x) · p(y₂|x,y₁) · p(y₃|x,y₁,y₂) ⋯，生成的时候顺手就算出来了。
- **MDLM**：同一份最终代码 y，可以由**无数种揭开顺序**得到。比如可以先揭第 5 个词再揭第 2 个，也可以反过来，每种顺序的概率都不同。π(y|x) 等于所有顺序的概率之和，而 400 多个位置的排列数是天文数字，根本算不出来。

这是 DLM 做 RL 的核心难点，也是各篇论文方法分歧的根源。

> **注意区分两个量**：算不出来的是 π(y|x)，即"最终得到这份代码"的总概率。但策略梯度类算法（GRPO / DAPO / RLOO / PPO-clip）其实只需要"这一次实际生成过程"的概率 π(τ)，这个能精确算，见下面的路线 B。常规算法能不能用、RL 阶段需要哪些模型，详见 [03-RL算法与模型.md](03-RL算法与模型.md)。

### 3.3 两条路线

**路线 A：用近似值代替（d1、DiffuCoder、SPG 等论文的做法）**

用训练时的 ELBO（完形填空 loss）来近似 log π。比如 d1：把答案全部遮住，跑一次模型，看每个位置上原词的预测概率。
- 优点：便宜，只需一次前向。
- 缺点：ELBO 只是一个下界，而且它对应的"策略"和实际采样时用的策略并不一致。相当于在优化一个近似的量。

**路线 B：轨迹法。不问"这份答案的概率"，而问"刚才这一次生成过程的概率"**

生成时把每一轮都记录下来：这一轮画布是什么状态、揭开了哪几个位置、各填了什么词。那么：

```
log π(这次生成过程) = Σ_每轮 Σ_这轮揭开的位置  log p_θ(填进去的词 | 这一轮的画布) + 常数
```

公式里的"常数"来自"哪些位置被揭开"那部分硬币。它和模型参数无关，求梯度时直接消失。

**小例子**：

```
第 1 轮画布: [题目] [M]  [M]   [M]    揭开位置 2，填 "trays"，模型给它的概率是 0.6
第 2 轮画布: [题目] [M]  trays [M]    揭开位置 1 和 3，填 "def"（概率 0.9）和 "="（概率 0.8）

log π = log 0.6 + log 0.9 + log 0.8
```

可以这样理解：AR 是"每步在固定位置选 1 个词"，MDLM 轨迹是"每步在随机位置选几个词"。两者本质上都是一串决策，所以策略梯度公式可以照搬。而且这个值是**精确的**，对应的正是评测时使用的那个采样策略。

**代价**：算梯度时，要把每一轮的画布重新喂给模型做前向和反向。128 轮就要做 128 次，太贵。解决办法是每条轨迹随机抽 8 轮来算，结果乘以 128/8 补回来，这样仍然是无偏估计。170M 的模型负担得起，这是小模型做 RL 的一个优势。

**我的建议**：主线走路线 B，因为它精确，而且和评测用的策略一致。时间够的话再实现路线 A 做对照，"精确 vs 近似哪个效果好"本身就是面试时能讲的一个小研究问题。

### 3.4 其他工程要点

- **奖励来自执行代码**：要加超时，防止死循环；要限制 import，防止执行危险代码。仓库自带沙箱，但它的超时机制只能在主线程使用，RL 里需要改成多进程。
- **训练稳定性**：学习率要小；要监控**熵**（模型输出分布的不确定程度）。熵迅速掉到接近 0，说明模型只会写一种答案了，这叫熵崩塌。
- **从哪个模型开始做 RL**：常规流程是 base → SFT → RL。时间够的话，可以再加一组"直接从 base 做 RL"作为对照。

## 4. 最后怎么比较，能得出什么结论

**统一设置**：所有模型用相同的步数 K、温度 T、随机种子，每题生成 1 份答案，跑完整的 1319 道 test 题。

**必须加"只改解码、不训练"的对照组**：
- base + 低温；
- base + 每轮优先揭开模型最有把握的位置；
- base + 多数投票。

否则面试官一定会问："你 RL 涨了 10 个点，那光降温是不是也能涨这么多？"

**最值得做的分析：RL 是教会了模型新本事，还是只是让它不再手滑？** 工具是 pass@k：每题采 k 份答案，至少一份对就算这题做对。
- pass@64 衡量模型"有没有能力做对"；
- pass@1 衡量模型"能不能一次做对"。

如果 RL 之后 pass@1 大涨，而 pass@64 不变甚至下降，说明 RL 主要是把分布收窄了，并没有学会新的解法。这和 §1.4 里"降温就能翻倍"的现象正好呼应，也和近期 AR 大模型上的一个热门结论一致（Yue et al. 2025, arXiv 2504.13837）。

## 5. 需要掌握的技术点（面试会追问）

| 技术点 | 要能讲清楚什么 |
|---|---|
| MDLM 训练 | 加噪就是遮盖；遮盖比例随机；1/t 权重和 ELBO 的关系 |
| MDLM 采样 | 揭开规则；步数和"同轮独立采样"误差的关系；温度的作用 |
| 和 Duo、S-FLM 的区别 | Duo：已填的词还能被改；S-FLM：在连续的 embedding 球面上流动 |
| SFT | 对 DLM 就是同一个 loss 换数据；只训答案部分；过拟合风险 |
| 策略梯度 / GRPO | 优势怎么算；组内基线；全对全错为什么没信号；PPO clip；KL 正则 |
| DLM 做 RL 的难点 | log π 为什么算不出来；ELBO 近似和轨迹法各自的取舍 |
| 可验证奖励 | 沙箱执行、超时、奖励稀疏问题 |
| 评测统计 | 置信区间、配对检验、pass@k、训练 / 调参 / 测试分离 |
