# RL 阶段：用什么模型、常规算法能不能用

> 写于 2026-10-29。回答的问题：01 文档说 MDLM 的 π(y|x) 算不出来，那 PPO / DPO / GRPO / DAPO 这些常规算法还能用吗？RL 阶段需要哪些模型？
> 前置阅读：[01-方向一讲解.md](01-方向一讲解.md) §3。相关决策：[02-决策记录.md](02-决策记录.md) D11、D12。

---

## 0. 结论

- **RL 阶段用的就是 MDLM 本身**（SFT 之后的版本），不需要另外训练奖励模型或价值模型。
- **GRPO、DAPO、RLOO 可以直接用，PPO 的 clip 也能用。** 带 critic 的完整 PPO 能做但不划算。DPO 能做，但有一个额外的坑。
- **为什么能用**：01 里说算不出来的是 **π(y|x)**，即"最终得到这份代码"的总概率，要对所有揭开顺序求和。但策略梯度类算法只需要 **π(τ)**，即"这一次实际发生的生成过程"的概率。后者可以精确计算。

## 1. RL 阶段涉及哪些模型

| 角色 | 是什么 | 需要吗 | 显存 |
|---|---|---|---|
| 策略模型 π_θ | SFT 后的 MDLM，要训练 | 必需 | 参数 + Adam 状态约 2.7 GB |
| 旧策略 π_old | 本批 rollout 时的参数，用于算重要性比率 | **不用单独存一份模型**：rollout 后先算好每个动作的 log-prob 存下来。只更新一次时，它就等于 π_θ | — |
| 参考模型 π_ref | 冻结的 SFT 模型，用来算 KL | 可选；初期不加，出现熵崩塌或输出跑偏再加 | bf16 约 0.3 GB |
| 奖励 | 沙箱执行代码，答案对得 1 分 | 不是模型 | — |
| 价值模型（critic） | 估计"当前状态之后能拿多少分" | 只有 PPO 需要；GRPO / DAPO 不需要 | — |

170M 的模型，几份模型加起来也不占多少显存，真正吃显存的是 rollout 时的激活。

## 2. 为什么 π(y|x) 算不出来，RL 照样能做

### 2.1 策略梯度只需要"实际发生的那条轨迹"的概率

RL 的目标是让期望得分变高：J(θ) = E[R(y)]。最终代码 y 是由一条生成轨迹 τ = (z_1 → z_{t_1} → … → z_0) 产生的，奖励只看最终的 y。

对轨迹的分布用一次 log-derivative trick：

$$\nabla_\theta J = \mathbb{E}_{\tau \sim \pi_\theta}\big[\, R(y(\tau)) \cdot \nabla_\theta \log \pi_\theta(\tau) \,\big]$$

这个等式对任何"能采样、能算 log 概率"的随机过程都成立。它从头到尾**不需要把不同揭开顺序加起来**：采样到哪条轨迹，就只算那一条。

轨迹的概率可以拆开：

$$\log \pi_\theta(\tau) = \sum_k \Big[ \underbrace{\log q(\text{第 } k \text{ 轮揭开哪些位置})}_{\text{与 } \theta \text{ 无关，梯度为 0}} + \sum_{i \in \mathcal{U}_k} \log p_\theta\big(z_0^i \mid z_{t_k}\big) \Big]$$

### 2.2 直观理解：掷骰子决定填哪格，你决定填什么

把生成想成一个游戏：每一轮由骰子决定这轮填哪几格（揭开顺序，与模型无关），由你决定每格填什么（模型的选择）。

想变强，你不需要知道"所有可能的骰子序列下，最终得到这张盘面的总概率"。你只需要知道：在实际玩的这一局里，你做的每个选择有多大概率，以及这局最后赢了没有。赢了就让这些选择更可能出现，输了就让它们更不可能出现。

揭开顺序的随机性相当于"环境的随机性"，就像游戏里的骰子。

图像扩散模型的 RL（DDPO）和 DLM 上的 TraceRL 用的都是这个思路。

### 2.3 那 01 文档里说的"算不出来"错了吗

没错，只是它针对的是另一个量：
- **π(y|x) 算不出来**：要对所有揭开顺序求和。
- **π(τ) 能精确算**：只算实际发生的那一条轨迹。

路线 A（d1 等）想估计的是前者，所以只能用 ELBO 去近似；路线 B（轨迹法）用的是后者，所以是精确的。

## 3. AR ↔ MDLM 对照：常规算法怎么"搬过来"

| | AR | MDLM（轨迹视角） |
|---|---|---|
| 状态 | 题目 + 已生成的前缀 y_<i | 当前画布 z_{t_k} |
| 动作 | 下一个 token | 第 k 轮新揭开的几个 token（给定画布时彼此独立） |
| 单个动作的 log-prob | log p(y_i \| x, y_<i) | log p_θ(z_0^i \| z_{t_k}) |
| 重要性比率 | 每个 token 的 p_θ / p_old | 同左，对每个被揭开的 token 算 |
| 一条样本的动作总数 | 生成长度 L | 也约是 L（每个位置只被揭开一次） |
| 算全部 log-prob 要几次前向 | **1 次**（因果 mask，所有前缀一次算完） | **K 次**（每一轮的画布都不同） |
| 需要存什么 | 生成的 token | 生成的 token + 每个位置在第几轮被揭开（L 个整数），据此能还原每一轮的画布 |

**唯一实质的差别是成本**（倒数第二行）。

解决办法：每条轨迹只抽 m 轮来算（例如 128 轮里分层抽 8 轮），结果乘以 K/m，梯度估计仍然无偏。

粗算（每次 RL 更新：128 条 rollout × 128 步，抽 8 轮）：
- rollout：128 × 128 = 16,384 次前向；
- 训练：128 × 8 = 1,024 次前向 + 反向，约等于 3,000 次前向；
- 如果再重算旧 log-prob、加参考模型，各再加约 1,000 次前向；
- **训练部分约为 rollout 的 20–30%**，大头仍然是 rollout。

**为什么画布能还原**：MDLM 的 token 一旦揭开就不再改。所以第 k 轮的画布 = "第 k 轮之前已揭开的位置填最终 token，其余位置填 [M]"。这个性质 Duo 没有，Duo 做轨迹法就得把每一轮的画布都存下来。

## 4. 常规算法逐个看

| 算法 | 需要什么 | 在 MDLM 上怎么拿到 | 可行性 | 建议 |
|---|---|---|---|---|
| REINFORCE / RLOO | ∇ log π(τ) + 基线 | 轨迹 log-prob | 直接可行 | 最简单的起点 |
| GRPO | 同上 + 组内标准化的优势 + clip 后的比率 | 比率对每个被揭开的 token 算 | 直接可行 | **主线** |
| DAPO | GRPO + clip-higher、动态采样、token 级 loss、去掉 KL | 这些改动都不依赖 log π 怎么算 | 直接可行 | **主线默认带上这些技巧** |
| PPO（带 critic） | 再加价值网络 V(状态) 和 GAE | V(画布)：在 DiT 上加一个价值头 | 能做但不划算 | 不做 |
| DPO | 偏好对 + 放在 sigmoid 里的 log π_θ / π_ref | (a) 自采样对的轨迹 log-prob；(b) ELBO 近似（LLaDA 1.5 的 VRPO） | 能做，有坑 | 可选对照 |

### 4.1 GRPO

- **on-policy、每批只更新一次时**，比率恒等于 1，clip 不起作用。这时 GRPO 就是"用组内均值做基线的 REINFORCE"。只有同一批数据更新多次时，clip 才起作用。
- **标准差归一化**：GRPO 默认把优势除以组内标准差。Dr. GRPO（arXiv 2503.20783）指出这会引入题目难度上的偏差：二值奖励下，几乎全对或几乎全错的题权重会被放大。这一点作为消融项。

### 4.2 DAPO 的四个技巧在 MDLM 上的对应

| DAPO 技巧 | 作用 | MDLM 上怎么用 |
|---|---|---|
| clip-higher（ε_low=0.2, ε_high=0.28） | 上界放宽，给低概率的好动作更多提升空间，缓解熵崩塌 | 直接用 |
| 动态采样 | 丢掉全对 / 全错的组 | 直接用（原计划里已有） |
| token 级 loss | 按全批 token 总数归一化，不按每条样本平均 | 按"被揭开的 token 总数"归一化；pad 算不算 token 见 D20 |
| 超长惩罚 | 惩罚超出长度上限的回答 | 画布固定 512，没有"超长"问题；改成格式惩罚：没写出 EOS、没定义函数 |

### 4.3 为什么不做带 critic 的 PPO

- 要多训一个价值网络，评估"一张写了一半的画布最后能拿多少分"。这又多一套超参，还需要预热。
- 奖励是最后才给的二值分数，critic 很难学准。
- 对于可验证奖励，GRPO 的组内基线已经是成熟做法，不需要 critic。
- 一周时间，不值得。

### 4.4 DPO：能做，但有一个坑

1. **log π 在 sigmoid 里面**：DPO 的 loss 是 −log σ(β · [对数比率之差])。抽步估计的 log π 本身无偏，但经过 sigmoid 这个非线性函数后，loss 的估计就有偏了。策略梯度没有这个问题，因为它对 log π 是线性的。
   - 办法一：每对样本都算满 K 轮。K=64 时，5k 对大约要 2–4 卡时一轮，要在 D1 实测。
   - 办法二：接受偏差，或者用 VRPO 的方差缩减方法。
2. **轨迹版 DPO 理论上成立**：在轨迹上推导"最大化奖励 − β·KL"，和在 y 上推导一样走得通。而且轨迹上的 KL ≥ 最终输出上的 KL，正则更强。
3. **它是离线的**：用 RFT 采样得到的"同一题一对一错"构造偏好对，不需要在线 rollout。和在线 GRPO 对比，可以回答"离线偏好 vs 在线 RL"这个问题。

## 5. 实现时的坑

| 坑 | 问题 | 做法 |
|---|---|---|
| 温度一致 | rollout 用 T 采样，实际的采样分布是 softmax(logits/T) | 算 log-prob 时用同一个 T |
| 精度一致 | 采样用 float64，训练时重算 log-prob 用 bf16，两者有微小差异，比率在第一次更新前就不等于 1 | 旧 log-prob 也用训练时的同一条代码路径重算，不直接用采样器给的值。AR 模型做 RL 时推理引擎和训练框架不一致，是同一类问题 |
| 精度一致（10-30 实测，`tests/test_rl_logprob.py`） | 更准确的说法：输出层给出 bf16 logits，采样器（同上游）在 bf16 下做 log-softmax 再转 float64，所以采样器的 log-prob 带 bf16 舍入 | 训练用 fp32 log-softmax（`rl/logprob.py` 默认），旧 / 新都走它，更新前比率严格为 1（实测误差 0）。与采样器的差：逐 token 平均 2e-3、最大 0.061（一个 bf16 ulp），单条轨迹最多 0.43 nats。若训练不稳，可以用记录下的 `sampler_logp` 做截断重要性采样修正 |
| 揭开顺序必须随机 | 如果 rollout 用 confidence remasking（按置信度挑位置），"揭开哪些位置"就依赖 θ，公式里那一项不再是常数；而且确定性挑选没有梯度 | RL 训练和主评测都用随机的 ancestral 采样；confidence remasking 只作为额外的解码对照（D16） |
| 最后一步 | 最后一轮会把剩下的 mask 一次性全部揭开 | 这些也是动作，要算进去 |
| 抽步要分层 | 纯随机抽 8 轮，可能全抽到前期或后期 | 把 K 轮分成 m 段，每段抽 1 轮 |

## 7. 为什么选 GRPO

### 7.1 真正要选的是"基线从哪来"

所有策略梯度方法的骨架都是同一个公式：

$$\nabla J \approx \sum_i \big(R_i - b\big)\, \nabla \log \pi_\theta(\tau_i)$$

基线 b 不改变梯度的期望，只影响方差。最理想的基线是"这道题的期望得分"，也就是模型在这道题上的成功率 p(x)。不同方法的区别，主要在于 b 怎么估计：

| 方法 | 基线 b 从哪来 | 在本任务上的问题 |
|---|---|---|
| REINFORCE（全局基线） | 所有题的平均分（滑动平均） | GSM8K 题目难度差异很大，全局基线会让信号错位，见 7.2 |
| PPO | 训练一个价值网络 V(状态) | 要多训一个模型；奖励只在最后给、只有 0/1，难学准；DLM 的"状态"是随机揭开的半成品画布，更难估 |
| ReMax | 同一题 greedy 解码一次的得分 | 单个样本做基线，噪声大 |
| **GRPO / RLOO** | **同一题采 G 个答案，用组内平均分** | 要多采样；但 170M 模型采样便宜 |
| RFT（拒绝采样微调） | 没有基线：只用做对的样本做 SFT | 不会"压低"错误答案；是最便宜的退路 |
| DPO | 不用基线，用偏好对 | 离线，不探索新答案 |

### 7.2 为什么必须"按题"给基线

设两道题：简单题成功率 0.9，难题成功率 0.1。

| | 全局基线 b = 0.5 | 按题基线 b = p(x) |
|---|---|---|
| 简单题做对（常见） | +0.5，大力强化本来就会的 | +0.1，几乎不动 |
| 简单题做错（少见） | −0.5 | **−0.9，重点纠正偶发错误** |
| 难题做对（少见） | +0.5 | **+0.9，重点强化罕见的成功** |
| 难题做错（常见） | −0.5，大量压低 | −0.1，几乎不动 |

按题基线让学习信号集中在"出乎意料"的结果上：会做的题偶尔做错、不会的题偶尔做对。这正是 RL 想要的。

### 7.3 为什么 GRPO 适合这个任务

1. **奖励是可验证的 0/1**：执行代码就能判分，不需要奖励模型，也就不需要 DPO 那种隐式奖励。
2. **采样便宜**：GRPO 的代价是每题采 G 个答案。对 8B 模型这很贵，对 170M 模型很便宜。
3. **起点合适**：组内要"有对有错"才有信号。按每题准确率都相同粗算：

   | 每题准确率 p | G=8 时有对有错的概率 | G=16 |
   |---|---|---|
   | 0.05 | 0.34 | 0.56 |
   | 0.10 | 0.57 | 0.81 |
   | 0.18（MDLM 平均） | 0.80 | 0.96 |
   | 0.90 | 0.57 | 0.81 |

   MDLM 的平均准确率 18%，而且 T=1 和 T=0.1 差距很大，说明很多题是"时对时错"的。这正是 GRPO 能吃到信号的区域。难题想有信号，就得把 G 开大，这是 G 取 8 还是 16 的取舍。
4. **不需要价值网络**：在 DLM 上估计"半成品画布的价值"既不自然也难训，GRPO 刚好绕开了这个问题。
5. **和文献可比**：d1、wd1、SPG、coupled-GRPO、TraceRL 都以 GRPO 类目标为基础，结果好对比，面试官也熟悉。
6. **简单好调**：一周内要能 debug 完。

### 7.4 GRPO 和 RLOO、REINFORCE 其实差别很小

在本项目的设置下（on-policy，每批只更新一次）：
- **比率恒等于 1，clip 不起作用**，GRPO 就是"带组内基线的 REINFORCE"。
- **GRPO 与 RLOO 只差两个细节**：
  - GRPO 的组均值包含自己，RLOO 不包含（留一法）。两者只差一个常数因子 (G−1)/G，方向一样。
  - GRPO 再除以组内标准差。二值奖励下标准差是 √(p(1−p))，会放大成功率接近 0 或 1 的题。Dr. GRPO 认为这是一种难度偏差，所以把它列为消融项。

所以准确地说，选的是**"组内蒙特卡洛基线、不要价值网络、在线采样"这一类方法**。叫 GRPO，是为了和文献的叫法、超参习惯保持一致。实现时把"是否除以标准差""是否包含自己"做成开关，RLOO 和 Dr. GRPO 都能顺手跑。

### 7.5 什么情况下 GRPO 不合适

- 起点准确率接近 0（例如 FLM 的 0.3%）：几乎所有组全错，没有信号。这时要先做 SFT，或者用格式分等更密的奖励。
- 奖励稠密、连续，或者是多轮交互的长任务：价值网络的优势会显现出来。
- 采样很贵（大模型、长输出）：组采样的成本会成为主要瓶颈。

本任务这三条都不成立。
