## B. demo 设计

### B.1 目标

现场展示"同一个题目，原始模型 vs RL 后模型"的差别，让观众直观看到改进在哪里。**不要只放一个成功的例子**，也要放一个失败的，并解释失败模式（题目明确说"没做出来的部分说明试了什么、卡在哪里"）。

### B.2 脚本

`code/scripts/demo.py`：给定题目编号（dev 或 test 的 index）和 checkpoint 列表，用同一 seed 生成、执行、打印结果与判定。

```bash
# 指定题目：dev 中的第 3、17、42 题，baseline 与 RL 定稿各生成一次
python -m scripts.demo --split dev --ids 3 17 42 \
  --ckpts base:/root/autodl-tmp/checkpoints/tinygsm/mdlm.ckpt \
          rl:/root/autodl-tmp/rl_ckpt/1103-grpo-elbo-conv-fmt0.1-nokl/step400.ckpt
```

输出：每题一张卡片，包含题目、标准答案、两个模型各自的代码、执行得到的数字、判定（对 / 能跑但错 / 报错）。

### B.3 选题原则

1. **两道 RL 修好的题**：base 报错或算错、RL 答对。展示"能跑起来"这一类改进。
2. **一道都错的题**：展示失败模式（运行时错误或算错），并说明是哪一类原因。
3. **一道两道都对的题**：说明不是所有题都变好了。
4. 不要挑"看起来最漂亮"的个别案例而不说明抽样方式；报告里注明是按固定编号挑的。

### B.4 备选：录屏

如果现场演示有网络/时间风险，提前把上面的输出录成一段 1 分钟的视频或 GIF，现场播放；同时保留脚本可现场重跑。
