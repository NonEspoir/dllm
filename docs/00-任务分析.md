## 1. 方向选择：推荐方向一（SFT + RL），主模型 MDLM

### 1.1 为什么不选方向二：预算算不过来

- **可用算力**：按 4090 约 ¥2/小时（以平台实时报价为准），¥100 ≈ 50 卡时。4090 的 bf16 吞吐约为 H100 的 1/3–1/4，折合 **12–15 H100·小时**（估计）。
- **对比官方**：MDLM 完整训练一次要 182.7 H100·小时。题目要求 baseline 和改进方案训练量相同，每个方案只能分到 6–7.5 H100·小时，即**官方训练量的 3–4%**，约 8–10k 步。
- **后果**：
  - 官方训满 250k 步也才 18%。训练量只有 3–4% 时，GSM8K 准确率大概率是个位数（没有中间 checkpoint，无法验证）。
  - 1319 题在 p≈18% 时，95% CI 半宽 ≈ 1.96·√(0.18·0.82/1319) ≈ **±2.1pp**；个位数准确率时噪声相对更大。
  - 两个方案的 benchmark 差异会被噪声淹没，最后只能比 val loss，达不到题目要求的"对比 benchmark 分数"。
- **理论层面的额外障碍**：MDLM 的连续时间 NELBO 对 noise schedule 不变（Sahoo et al. 2024），只依赖 α 的端点。所以对 MDLM 来说，"改 noise schedule"只改变 Monte-Carlo 估计的方差，不改变优化目标，在极短训练里很难测出效果。S-FLM 的截断 schedule 是例外：它只在 [0, a] 的高噪声区训练，**改变了训练目标本身**——这也解释了为什么截断在 S-FLM 上效果大（Table 2：1.2 → 7.7）。

> 这一段即使不做方向二，也值得写进报告的理论部分。

### 1.4 有没有用更干净的数据训出来的 checkpoint？（D0 调研）

**先说清 TinyGSM 的质量**（TinyGSM 论文 arXiv 2312.09241，Sec 3 "Filtering"）：
- 做了的过滤：去掉太短、不含数字的题目，以及**不能执行**的代码。
- 没做的：原文是 "we do not check for the correctness of the question or the generated solutions, since the 'ground truth' solution is not available"。题目本身是合成的变体，所以没有标准答案可比。
- 作者也没用多数投票做过滤，理由是 GPT-3.5 只在简单题上前后一致。
- 错误解法的比例没人测过。作为参考，GPT-3.5 自己在 GSM8K 上的准确率是 77.4%（同一论文），所以错误比例可能不低。这只是推测。

**关键判断：数据噪声不是 MDLM 只有 18% 的主要原因**

| 模型（S-FLM 论文 Table 2 / Fig 3） | 训练数据 | GSM8K |
|---|---|---|
| AR，170M 级 | TinyGSM（同一份） | 53.9（采样）/ 63.3（greedy） |
| MDLM，170M | TinyGSM（同一份） | 18.0（T=1）/ ≈33（T=0.1） |

同一份带噪声的数据、相同规模，AR 能做到 54–63%，说明这份数据本身足以支撑 60% 左右的水平。MDLM 差的 30–45 个点主要来自建模和解码方式：任意顺序生成更难学，同一轮揭开的多个 token 又是独立采样的。换一个"数据更干净"的 checkpoint，解决不了这个主要矛盾。

**噪声反而正好是方向一的动机**：预训练学到的是"GPT-3.5 的解法分布"，错误解法也学进去了。SFT 用执行验证过的数据纠偏，RL 用可验证奖励直接优化"答对"。报告里可以这样把三个阶段串起来。

## 2. 原理要点（报告理论部分要讲清的）

### 2.1 MDLM（absorbing / masked diffusion）

**前向过程**：每个 token 独立，以概率 1−α_t 被替换成 `[MASK]`：

$$q(z_t \mid x) = \mathrm{Cat}\big(\alpha_t\, x + (1-\alpha_t)\, m\big)$$

**SUBS 参数化**：已揭开的 token 直接复制；预测分布里 `[MASK]` 的概率置零。

**训练目标（连续时间 NELBO）**：

$$\mathcal{L} = \int_0^1 \frac{\alpha_t'}{1-\alpha_t}\; \mathbb{E}_{q}\Big[\sum_{i:\, z_t^i = m} \log p_\theta(x^i \mid z_t)\Big]\, dt$$

其中 α'_t < 0，所以 L ≥ 0。本质是对被 mask 位置的交叉熵做加权；作变量替换后与 α_t 的具体形状无关。

**采样（ancestral）**：从 t 到 s<t，每个 mask 位置

- 以 (α_s − α_t)/(1 − α_t) 的概率被揭开，揭开时 token 从 p_θ(·|z_t) 采样；
- 否则保持 mask。

对应代码 `samplers.py:43` `absorbing_posterior_probs` 和 `:59` `sample_absorbing_posterior`。

**factorization 误差**：同一步揭开的多个 token 在给定 z_t 时条件独立，步数越少误差越大。这也是 MDLM 少步采样掉点的原因。

### 2.2 Duo（uniform-state diffusion）

- 前向过程是把 token 换成均匀随机的其他 token，而不是 `[MASK]`。所以已生成的 token 在后续步骤中**还能被改写**；MDLM 一旦揭开就固定。
- "Diffusion Duality"：对高斯扩散的隐变量取 argmax 就得到 uniform-state 离散扩散。借此可以把连续扩散的技巧（课程学习、consistency 蒸馏）迁移过来，做少步采样。
- 有时间条件（`time_conditioning: True`），ELBO 比 MDLM 复杂。

### 2.3 FLM / S-FLM（连续流）

- **共同点**：用确定性 ODE 把噪声运到数据，不做逐 token 因子化，理论上能避开 2.1 中的 factorization 误差。
- **FLM**：在 |V| 维 one-hot 空间里流动，每步都要和完整 embedding 表做乘法，训练贵；在 GSM8K 上 <1%。
- **S-FLM**：在 d 维单位球面 𝕊^{d−1} 上流动，用 slerp 把随机点运到干净 embedding。
  - 速度场：v(z) = Σ_k p_θ(k|z) · log_z(e_k)，即后验加权的 log map。
  - 关键观察：词表 embedding 在高维球面上分得很开，低噪声区的后验很快塌成 one-hot。所以把 schedule 截断到高噪声区，作者推出了截断阈值 α*(δ) 的闭式解。
  - 再加上自适应 schedule 和 𝕊-arch（激活也约束在球面上）。
  - top-1 velocity 解码相当于贪心，在 T=1 下明显有效（12.4 → 18.0），但偏离了精确的边缘流。

### 2.4 RL 在 DLM 上的核心难点：没有精确的 log π

AR 模型有精确的序列 log 概率：

$$\log \pi_\theta(y\mid x)=\sum_i \log p_\theta(y_i \mid x, y_{<i})$$

PPO / GRPO 的重要性比率、KL 都建立在它之上。DLM 只能给出 ELBO（下界），这是各种 DLM-RL 方法分歧的根源：

**(a) ELBO / 单步代理**

| 方法 | 做法 |
|---|---|
| d1 / diffu-GRPO | completion 全部 mask，prompt 随机 mask 15%，一次前向估计每个 token 的 log-prob |
| DiffuCoder / coupled-GRPO | 用一对互补 mask 降低估计方差 |
| SPG | 同时用 ELBO（下界）和 EUBO（上界）夹逼 |
| wd1 | 不用比率，改为加权似然目标 |

**(b) 把采样器当 MDP（轨迹法）**

在 ancestral 采样下，一条采样轨迹 z_1 → z_{t_{K−1}} → … → z_0 的概率可以精确分解：

$$\log \pi_\theta(\tau\mid x) = \sum_{k}\ \sum_{i \in \mathcal{U}_k} \log p_\theta\big(z_{0}^i \mid z_{t_k}\big) + \text{const}$$

- U_k 是第 k 步新揭开的位置。
- "哪些位置被揭开"由 (α_s−α_t)/(1−α_t) 决定，与 θ 无关，进常数项。
- 所以这个值是**精确的**，而且就是评测时用的那个策略——不需要任何近似。
- 代价：要对存下来的中间状态 z_{t_k} 重新带梯度做前向。可以每条轨迹随机抽 m 个步，乘以 K/m 做无偏估计（思路同 DDPO、TraceRL）。
- 170M 的模型恰好负担得起，这是小模型能做得比 8B 模型更"干净"的地方。

> 报告里可以把"精确轨迹似然 vs ELBO 代理"作为一个对照实验：同样的奖励、组大小和更新步数，只换 log-prob 的算法。

## 3. 实验设计

### 3.1 数据划分（题目明确要求训练、调参、最终测试分开）

| 用途 | 数据 | 规模 |
|---|---|---|
| 预训练 | TinyGSM | checkpoint 已用过 |
| SFT / RL 训练 | GSM8K train（去掉 dev） | 6,973 |
| 调参、选 checkpoint | GSM8K train 留出 | 500 |
| 最终测试 | GSM8K test | 1,319，只在定稿模型上跑 |

另外要做一次 **TinyGSM ↔ GSM8K test 的 n-gram 重叠检查**（例如 13-gram），在报告里说明污染情况。

### 3.2 SFT

**数据来源（两种）**：

- **A. 教师蒸馏**：
  - 用 DeepSeek / Qwen 把 GSM8K train 改写成 TinyGSM 风格（`def simple_math_problem() -> ...:`，docstring 放题目，最后 `return result`）。
  - 用同一个 sandbox 执行，只保留答案与 gold 一致的样本。
  - API 费用约 ¥10–30：约 7.5k 题 × 1.5 次尝试 × 约 300 输出 token，加上 few-shot prompt 的输入；具体取决于模型和当时价格。
  - 零成本备选：GSM8K 答案里有 `<<16-3-4=9>>` 式的计算标注，可以用脚本机械地转成 Python，答案天然正确。缺点是变量名没有语义，风格和 TinyGSM 不同。
- **B. 自我拒绝采样（RFT / STaR）**：
  - 让 MDLM 每题采 16 个解，保留做对的、去重后做 SFT。
  - 不花钱，复用 RL 的 rollout 代码，本身也是 RL 的天然 baseline（≈ 一轮 expert iteration）。

**训练设置**：
- loss 与预训练完全一致：MDLM NELBO，`train_on_prompt=False`，`train_on_pad=True`，长度 512。
- 小学习率（1e-5 到 3e-5 量级）、1–3 epoch、保留 EMA。
- 7k 条数据对 170M 模型很容易过拟合，以 dev 准确率为准选 checkpoint。

**要回答的问题**：TinyGSM 本身已经是"question → code"的条件训练，SFT 能带来的增量是什么——更贴近 GSM8K 分布？更干净（执行验证过）？如果提升小，就要解释原因。

### 3.3 RL

| 项 | 设计 | 理由 |
|---|---|---|
| 奖励 | 执行正确 = 1，否则 0；格式分（能编译、定义了函数）做消融 | 可验证的二值奖励；看稀疏性是否成为问题 |
| 算法 | GRPO / RLOO，每组 8–16 个采样 | 无需 value 网络；组内均值作 baseline |
| 更新 | 先做 on-policy 单次更新（重要性比率恒为 1），稳定后再考虑 PPO clip、多 epoch | 最不容易出 bug |
| 题目筛选 | 丢掉组内全对或全错的题（DAPO 式 dynamic sampling） | 这些题优势全为 0，浪费算力 |
| log-prob | 主线用 §2.4(b) 轨迹法；有时间再实现 (a) diffu-GRPO 做对照 | 精确且与评测策略一致 |
| rollout 步数 | 64–128 步 | 1024 步太慢；之后专门测步数泛化 |
| 温度 | rollout 用 T=1 保证探索；评测 T∈{1, 0.1} | — |
| 正则 | 先不加 KL，监控熵；出现熵崩塌再加 KL 或熵正则 | — |

### 3.4 统一评测协议

- 所有模型（base / SFT / RFT / RL）使用同一协议：
  - 相同步数：主设置在 D1 实测后定，候选 256；另报 1024 步复现值；
  - 相同温度：T∈{1, 0.1}；
  - 相同 seed，每题只生成 1 个解。
- 报告 bootstrap 95% CI。两个模型做的是同一套题，比较时用**配对检验**（McNemar / 配对 bootstrap），比独立 CI 更灵敏。
- 差距 <3pp 时措辞要谨慎。

### 3.5 必须加的免费对照组

不加的话，说不清 SFT/RL 的提升是否超过一个解码技巧：

1. base 模型降温到 T=0.1；
2. confidence-based remasking：每步揭开置信度最高的位置，而不是随机位置；
3. block / 半自回归解码：TinyGSM 的代码有很强的左到右结构，论文 Limitations 里也提到了；
4. 多数投票（采 k 个解，取出现最多的答案）。

## 4. 值得深挖的分析问题（面试亮点）

1. **RL 是教会了新能力，还是只锐化了分布？**
   - 对比"RL 模型在 T=1"和"base 模型在 T=0.1"。
   - 在 dev 上画 pass@k 曲线（k = 1, 2, 4, …, 64）。
   - 若 pass@1 上升而 pass@64 不变或下降，说明主要是锐化。与 Yue et al. 2025 在 AR 模型上的结论对照。
2. **步数鲁棒性**：在 64 步上做 RL，测 8 / 16 / 32 / 256 / 1024 步的表现。这是 DLM 特有的问题：RL 是否让模型对训练步数过拟合？
3. **解码顺序**：RL 前后，模型先揭开哪些位置？是否变得更接近从左到右？可以把揭开顺序可视化成热力图或动图，同时作为 demo 素材。
4. **错误分类**：把错误分成没有函数 / 语法错误 / 运行时错误 / 超时 / 答案错误，看 SFT 和 RL 分别修好了哪一类。
5. **熵与多样性**：训练过程中 token 熵、组内答案多样性的变化，是否出现熵崩塌。
6. **（可选）精确轨迹似然 vs ELBO 代理**：同等条件下比较两种 log-prob 估计的收敛速度和最终准确率。

## 6. 预算估计（估计，误差 ±50%，D1 实测校准）

> **10-30 起以 [05-开销预算.md](05-开销预算.md) 为准**（已定 AutoDL 的 4090）。本节保留 10-29 选卡时的分析过程。

### 6.1 方向一的算力几乎全花在采样上

单项估计（以 4090 为基准）：

| 项 | 估计 | 依据 |
|---|---|---|
| GSM8K test 全量评测，1024 步 | 约 1 h / 次 | 每 token 前向约 2.65e8 FLOPs × 512 × 1319 × 1024 ≈ 1.8e17，加上 float64 后验的开销 |
| 同上，256 步 | 约 15 min / 次 | 按步数缩放 |
| SFT | <1 卡时 | 7k 条 × 3 epoch，约 8.5e15 FLOPs |
| RFT 采样 | 约 2 卡时 | 7k 题 × 8 个 × 64 步 |
| RL | 每步 40–60 s；300 步约 4–5 卡时 | 每步 128 条 rollout × 128 步 + 抽步训练 |

评测、RFT 采样、RL rollout 加起来占总算力的七八成，而采样器默认用 float64。所以选卡时要看 FP64 吞吐和显存，不能只看 bf16 算力。

> **D0 复查更正**：用原版采样器在 4090 上按 batch 16 细算，每一步的 float64 运算（约 40–55 ms）比模型前向（约 27 ms）还慢。1024 步的全量评测可能要 1.5–2 小时，而不是上表的 1 小时；标准档可能涨到 45–60 卡时（约 ¥90–120）。
> 改用 §7 的「只在揭开位置采样」后，这部分开销基本消失，上表数字重新成立，甚至更低。**所以 D1 的第一件工程任务就是改采样器**，并验证新旧实现等价。

## 7. 已知的坑

- **依赖安装**：
  - 作者在 NGC 容器（`nvcr.io/nvidia/pytorch:25.02-py3`）里跑，依赖为 torch 2.7、lightning 2.5.1、transformers 4.45。
  - `requirements.txt` 里的 `git+https://github.com/EleutherAI/lm-evaluation-harness` 在国内网络大概率装不上。GSM8K 评测用不到这个包，可以删掉。
  - HF 下载设 `HF_ENDPOINT=https://hf-mirror.com`。本机 GitHub 直连超时，可以用 `codeload.github.com` 下 zip。
- **`flash_attn`**（10-29 更正）：`models/dit.py` 在文件开头就 import 它。MDLM / Duo 的注意力用的是 `F.scaled_dot_product_attention`，但旋转位置编码调用的是 `flash_attn` 的 Triton kernel `apply_rotary_emb_qkv_`（`dit.py:138`，在 `:421` 被调用）。4090 上正常安装即可；5090 或 Mac 上装不上时，要把它换成 torch 实现，约 10–20 行。
- **float64 采样不能随便关**：
  - 为什么要用 float64：Zheng et al.（arXiv 2409.02908）发现，用 float32 做 Gumbel 采样存在截断误差，效果上相当于降温，会让多样性下降、Gen PPL 虚低。关掉 float64 会改变采样分布，从而影响评测结论。
  - 显存：每个 [B, 512, 49152] 的 float64 张量，B=32 时 6.4 GB，B=64 时 12.9 GB，同时约有 3 份。所以 32GB 卡的 batch ≤32，80GB 卡可以开到 64–96。
  - 速度：5090 / 4090 的 FP64 只有 FP32 的 1/64，exp / log 等逐元素运算可能占采样时间的相当一部分。
  - **根本解法：只在本步要揭开的位置采样，分布与原实现完全一致**（D0 复查代码时发现，见下一条）。
- **采样器的两处冗余（MDLM 专用，Duo 不适用）**：
  - **冗余 1：全量采样后丢弃。** `sample_absorbing_posterior`（`samplers.py:59`）每一步都对 B×L 个位置做全词表的 float64 Gumbel 采样，然后只保留"仍为 mask 且被选中揭开"的位置，其余结果全部丢弃。
    - 每步每条序列平均只揭开约 生成长度 / K 个 token：1024 步时约 0.4 个，128 步时约 3–4 个。
    - 改法：先用 B×L 个均匀随机数决定揭开哪些位置，再**只在这些位置**取 logits，做 float64 的 softmax 和采样。
    - 各位置本来就相互独立，所以分布与原实现完全一致。
    - 效果：float64 的显存和计算开销降两三个数量级，FP64 弱的卡（4090 / 5090）不再吃亏，batch 也能开大。输出层（768×49k，约占每 token FLOPs 的 30%）同样可以只在这些位置算。
    - RL 需要的 log-prob 也只在这些位置算，正好复用。
  - **冗余 2：状态没变还重算。** MDLM 没有时间条件，同一个 x_t 的输出与 t 无关。1024 步时每步约 2/3 的序列没有任何变化，只对状态变了的序列做前向，可省约 2/3。256 步时约省 20%，64–128 步时基本没收益。
  - 注意：batch 内全部序列同时不变的概率极低，所以"整个 batch 跳过前向"没有用（D0 初稿写的"快 2 倍"不成立，已更正）。必须按序列跳过。
  - 验证：改完后在 dev 上用原实现和新实现各跑一次，准确率应在 CI 内一致；再做一个小单测，比较 token 边缘分布。
- **log-prob 只统计"从 mask 变成词"的位置**（10-29 更正）：batch 内 prompt 长度不同，`start_idx` 取最短的 prompt（`samplers.py:386`）。但 prompt 在初始化时就被 `_project_prefix` 写进画布，不是 mask，所以从不被采样。只要 log-prob 只统计"本步从 mask 变成词"的位置，prompt 就自动排除了。
- **EMA 权重**：要确认评测加载的是 EMA 权重。
- **pad 位置**：生成区约一半是 PAD。它们也是"动作"，但 log-prob 接近 0。计入与否会影响按长度归一化的方式，要在报告中说明选择。
- **超时机制**：`SIGALRM` 只能在主线程用，RL 奖励要放进 `multiprocessing` 进程池。
