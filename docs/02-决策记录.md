## 三、逐条说明（按编号，供查阅）

### D01 做哪个方向 —— 方向一（已定，10-29 确认）

- **推荐**：方向一（基于预训练 checkpoint 做 SFT + RL）。
- **理由**：
  - 方向二按官方配置完整训一次 MDLM 要 182.7 H100·小时。¥100 只够每个方案训到官方的约 2–5%，GSM8K 分数会被噪声淹没，做不出题目要求的 benchmark 对比（分析 §1.1、§1.1.1）。
  - 方向一的提升空间明确：MDLM 仅降温就能从 18% 涨到约 33%（分析 §1.2）。
  - 标准工作量在 ¥100 内（分析 §6）。
- **否决的备选**：方向二。如果自己垫钱，每个方案训到官方的 20% 约需 ¥440–585，且至少 4 卡并行。
- **何时重新评估**：除非预算能放大到几百元以上，否则不再讨论。

### D02 主模型 —— s-flm 仓库里的 MDLM checkpoint（已定，10-29）

> 命名澄清："s-flm" 是 HF 仓库 / 论文的名字，仓库里放了 AR、MDLM、Duo、FLM、CANDI、S-FLM 共 6 类模型的 checkpoint。D02 选的是其中的 **MDLM**（`tinygsm/mdlm.ckpt`），**不是** S-FLM 模型本身。

**第一层：为什么用这个仓库的 checkpoint，而不是外部模型**

- 预训练数据就是 TinyGSM，契合题目"围绕 TinyGSM"。
- 论文给了每个模型的 GSM8K 分数，可以用来校准复现。
- 训练、采样、评测代码统一。
- 170M 规模，¥100 内能做 RL。
- 外部候选的问题见 D04。

**第二层：为什么在仓库内选 MDLM**（RL 的三个硬条件，逐个筛）

| 条件 | MDLM | Duo | S-FLM | FLM / CANDI |
|---|---|---|---|---|
| ① 起点准确率（T=1） | 18.0 | 17.2 | 12.4 | 0.3 / 0.2 |
| ① GRPO 每组 8 个里"有对有错"的概率（按每题准确率都等于均值粗算） | 0.80 | 0.78 | 0.65 | 0.02 |
| ② 采样策略的 log π 怎么算 | 每轮只有新揭开的位置依赖 θ，共约 L 个项，精确 | 每轮**每个位置**的转移概率都依赖 θ（`keep_xt_prob` 用到 p_θ(x_t)），共 K×L 个项；可算但方差大、计算贵 | 默认 exact 模式是确定性 ODE，没有随机动作，策略梯度用不了；sample 模式下有 K×L 个离散动作，还要穿过连续状态做信用分配 | — |
| ③ 可借鉴的 RL 文献 | 最多（d1、wd1、SPG、coupled-GRPO、TraceRL 都基于 masked diffusion） | 很少 | 基本没有（连续流 RL 要参考图像领域的 Flow-GRPO 一类） | — |
| 降温的提升空间 | 18 → ≈33 | 17.2 → ≈36 | 12.4 → ≈18 | <0.5 |

- **FLM / CANDI**：被条件 ① 直接淘汰。准确率约 0.2–0.3%，98% 的组全错，RL 几乎拿不到学习信号。
- **S-FLM**：被条件 ② 淘汰。默认采样是确定性的，要做 RL 得先改造采样器，风险太大，所以只写可行性分析。
- **AR**：题目禁止。
- **MDLM vs Duo 是真正的二选一**：
  - 分数差 0.8pp，在 ±2.1pp 的置信区间内，可以算打平；低温下 Duo 还更高（36 vs 33）。
  - 所以选 MDLM 的决定性理由不是分数，而是条件 ② 和 ③：log π 只有约 L 项且精确，文献和工具最多。
  - 另外，D07 的采样器优化只适用于 MDLM。
- **Duo 的独特优势**：已生成的 token 还能被改写，有"自我纠错"能力，RL 也许能利用这一点。这正是把 Duo 列为加分项（D03）的原因：主线跑通后迁移过去，比较两类扩散在 RL 下的表现。
- **代码依据**：`samplers.py:59`（MDLM）、`samplers.py:112`（Duo）、`samplers.py:556`（S-FLM velocity）。

### D04 是否换"数据更干净"的 checkpoint —— 不换（待你确认）

- **理由**：
  - 同一份 TinyGSM 数据上，AR 170M 能做到 54–63%。说明数据噪声不是 MDLM 只有 18% 的主因（分析 §1.4）。
  - 候选 checkpoint 各有硬伤：
    - SMDM-GSM8K：已经做过 SFT；成本约 4 倍；58.5 分无法归因到数据质量。
    - LLaDA-8B：太大。
    - Dream 等：由 AR 权重转来，处于题目规则的灰区。
- **替代方案**：用 D10 的 SFT 消融，在方向一内部受控地回答"数据对错有多大影响"。

### D05 算力卡型 —— 重新讨论中（R17，10-30）

> **R17 更新**：R13 定 4090 时预算还卡在 ¥100。D24 放开预算后，时间成了硬约束，所以建议改为 **A800 单卡**：
> - 速度约为 4090 的 1.7–2 倍，D3、D5、D6 的计算时间都能明显缩短；
> - 80GB 显存，大 batch 和加分项 Duo 都不用为显存操心；FP64 强，原版采样器复现只要约 0.5 小时；
> - Ampere 架构，环境成熟。

> 代价：一周约 ¥390（按 ¥6/h × 65 小时假设），比 4090 多约 ¥250。嫌贵或租不到就仍用 4090。不选 5090：只比 4090 快 30–50%，却有配环境的风险。
>
> 多卡：AutoDL 一个实例可租 1–8 张卡，但 170M 模型单卡就够，多卡只用于并行评测（仓库代码原生支持按卡分题）和同时跑两组实验。建议 D1–D4 单卡，D5–D6 视情况加到 2 卡；租时挑空闲卡 ≥ 2 的主机，方便以后升配。
>
> 以下是 R13 时的原始记录。


- **候选**：

  | 卡 | 优点 | 风险 |
  |---|---|---|
  | 4090 | 最便宜 | FP64 弱，24GB 显存 |
  | 5090 | 估算最省钱 | 新架构，环境可能踩坑 |
  | A800 | 80GB 显存、FP64 强、生态成熟 | 单价高 |

- **测法**：每张卡跑一次「dev 200 题 × 256 步」评测，原版和改后的采样器各一次，记录耗时和峰值显存，每张约 ¥1–2。
- **判定标准**：
  - 改后的采样器跑全量 test（256 步）≤ 20 分钟；
  - 一个 RL 步（128 条 rollout × 128 步）≤ 60 秒；
  - 在满足上面两条的卡里，选"每次评测实际花费"最低的。
- **附加规则**：5090 的环境 1 小时内配不通，就直接换 A800。
- **依据**：分析 §6.3。
- **10-29 修订建议：D1 只租一种卡开工，不再三张都测。**
  - 原因一：时间比钱紧。每换一张卡都要重新配环境、下载 checkpoint，约 0.5–1 小时。
  - 原因二：改完采样器（D07）后，4090 的 FP64 和显存短板基本消失，三张卡在"每次评测的花费"上差距不大。
  - 顺序：**有 4090 就用 4090**（生态成熟、单价最低；RL 训练用梯度累积即可放进 24GB）→ 没有就用 **A800**（最稳，但标准档接近 ¥100 上限）→ **5090 放最后**（环境风险最大）。
  - 只有所选卡不满足上面的判定标准时才换卡。

### D07 采样器改造（已定，10-30）

- **改法（10-30 补充）**：不改原文件里的已有代码，而是**新增**一个采样器类（暂名 `FastAncestralSampler`）和对应的配置文件，用配置切换新旧版本。原版保留，用于 D1 复现、等价性验证和回退。

- **内容**：
  1. 先决定本步揭开哪些位置，**只在这些位置**取 logits 并做 float64 采样；
  2. 1024 步评测时，只对状态发生变化的序列做前向。
- **理由**：原实现对全部位置做 float64 采样后再丢弃，在 4090 上比模型前向还慢（分析 §6.1 更正说明、§7）。
- **约束**：
  - **不关闭 float64**。float32 的 Gumbel 采样等效于降温，会改变评测结论（Zheng et al., arXiv 2409.02908）。
  - 改完必须验证与原实现等价：dev 准确率在 CI 内一致，并用单测比较 token 边缘分布。
- **适用范围**：只适用于 MDLM；Duo 的已填 token 还会被改写，不适用。

### D11 RL 算法与奖励（待你确认）

> 各常规算法（PPO / DPO / GRPO / DAPO / RLOO）在 MDLM 上的可行性分析见 [03-RL算法与模型.md](03-RL算法与模型.md) §4。为什么选 GRPO 见同一文档 §7：实际选的是"组内基线、无价值网络、在线采样"这一类方法，GRPO / RLOO / Dr. GRPO 的差别做成开关。

| 项 | 设计 |
|---|---|
| 算法 | GRPO，组大小 8–16，带 DAPO 技巧：clip-higher、动态采样、token 级 loss；标准差归一化作消融（Dr. GRPO） |
| 奖励 | 执行正确 = 1，否则 0；格式分作消融 |
| 更新方式 | 先 on-policy 单次更新；稳定后再考虑 PPO clip、多 epoch |
| 题目筛选 | 丢掉组内全对或全错的题 |
| 正则 | 初期不加 KL，监控熵；出现熵崩塌再加 |
| 超参 | 学习率等在 D4 小规模 debug 时定 |
| 可选对照 | 离线 DPO：用 RFT 的"一对一错"构造偏好对；注意 log π 在 sigmoid 里，抽步估计会让 loss 有偏 |
| 不做 | 带 critic 的 PPO：要多训一个价值网络，奖励稀疏，GRPO 的组内基线已经够用 |

详见分析 §3.3。

### D12 RL 的 log-prob 计算 —— 主线轨迹法（待你确认）

- **路线 B（主线）**：把采样器当作 MDP，log π = Σ（每轮新揭开位置的 log p）。这个值是精确的，与评测策略一致。每条轨迹随机抽约 8 轮带梯度重算，做无偏估计。
- **路线 A（可选对照）**：d1 式的 ELBO 代理。便宜，但只是近似。
- "精确 vs 近似"的对比可以作为一个小研究问题（分析 §2.4，讲解 §3.3）。

## 四、否决的方案（保留理由，报告「无效 / 放弃的尝试」可用）
