### D02 主模型 —— s-flm 仓库里的 MDLM checkpoint（已定，10-29）

> 命名澄清："s-flm" 是 HF 仓库 / 论文的名字，仓库里放了 AR、MDLM、Duo、FLM、CANDI、S-FLM 共 6 类模型的 checkpoint。D02 选的是其中的 **MDLM**（`tinygsm/mdlm.ckpt`），**不是** S-FLM 模型本身。

**第一层：为什么用这个仓库的 checkpoint，而不是外部模型**

- 预训练数据就是 TinyGSM，契合题目"围绕 TinyGSM"。
- 论文给了每个模型的 GSM8K 分数，可以用来校准复现。
- 训练、采样、评测代码统一。
- 170M 规模，¥100 内能做 RL。
- 外部候选的问题见 D04。

**第二层：为什么在仓库内选 MDLM**（RL 的三个硬条件，逐个筛）

| 条件 | MDLM | Duo | S-FLM | FLM / CANDI |
|---|---|---|---|---|
| ① 起点准确率（T=1） | 18.0 | 17.2 | 12.4 | 0.3 / 0.2 |
| ① GRPO 每组 8 个里"有对有错"的概率（按每题准确率都等于均值粗算） | 0.80 | 0.78 | 0.65 | 0.02 |
| ② 采样策略的 log π 怎么算 | 每轮只有新揭开的位置依赖 θ，共约 L 个项，精确 | 每轮**每个位置**的转移概率都依赖 θ（`keep_xt_prob` 用到 p_θ(x_t)），共 K×L 个项；可算但方差大、计算贵 | 默认 exact 模式是确定性 ODE，没有随机动作，策略梯度用不了；sample 模式下有 K×L 个离散动作，还要穿过连续状态做信用分配 | — |
| ③ 可借鉴的 RL 文献 | 最多（d1、wd1、SPG、coupled-GRPO、TraceRL 都基于 masked diffusion） | 很少 | 基本没有（连续流 RL 要参考图像领域的 Flow-GRPO 一类） | — |
| 降温的提升空间 | 18 → ≈33 | 17.2 → ≈36 | 12.4 → ≈18 | <0.5 |

- **FLM / CANDI**：被条件 ① 直接淘汰。准确率约 0.2–0.3%，98% 的组全错，RL 几乎拿不到学习信号。
- **S-FLM**：被条件 ② 淘汰。默认采样是确定性的，要做 RL 得先改造采样器，风险太大，所以只写可行性分析。
- **AR**：题目禁止。
- **MDLM vs Duo 是真正的二选一**：
  - 分数差 0.8pp，在 ±2.1pp 的置信区间内，可以算打平；低温下 Duo 还更高（36 vs 33）。
  - 所以选 MDLM 的决定性理由不是分数，而是条件 ② 和 ③：log π 只有约 L 项且精确，文献和工具最多。
  - 另外，D07 的采样器优化只适用于 MDLM。
- **Duo 的独特优势**：已生成的 token 还能被改写，有"自我纠错"能力，RL 也许能利用这一点。这正是把 Duo 列为加分项（D03）的原因：主线跑通后迁移过去，比较两类扩散在 RL 下的表现。
- **代码依据**：`samplers.py:59`（MDLM）、`samplers.py:112`（Duo）、`samplers.py:556`（S-FLM velocity）。

### D03 其他模型的角色（已定，R31：Duo 只当加分项，S-FLM 只写分析）

> **R31 定下**：Duo 只当加分项，SFT 和 GRPO 主线跑通、报告框架搭好后有余量再考虑，不提前写；S-FLM 只写可行性分析，不动手。

- **依据**：
  - Duo 的优点是已生成的 token 还能被改写（"自我纠错"），RL 也许能利用；但没有 MDLM"揭开后不再变"的性质，轨迹法要存下每一轮的画布，成本高。所以不适合当主线，适合有余量时验证"同一套方法能否迁移"。
  - S-FLM 每步每个位置都是一个动作，方差极大，没有可借鉴的 RL 文献。
- **否决的备选**：把 Duo 迁移列为必须项（会挤占主线和报告的时间）。


**否决的选项及理由（R33 补）**

| 选项 | 为什么不选 |
|---|---|
| 确定做 Duo 迁移 | Duo 已生成的 token 还会被改写，没有 MDLM"揭开后不再变"的性质：MDLM 的轨迹只要存每个位置的揭开轮次就能还原每轮画布，Duo 必须把每一轮的完整画布都存下来，采样器和 log-prob 计算都要另写一套。主线 RL 还没跑通，提前承诺会挤占主线和报告的时间 |
| 彻底不做 Duo | 省心，但等于主动关掉一个加分点。"只当加分项"不提前花时间，有余量时还能做，严格优于直接放弃 |
| S-FLM 也动手 | 每步每个位置都是一个动作，方差极大；没有可借鉴的 RL 文献；不适合一周的项目 |

### D07 采样器改造（已定，10-30）

- **改法（10-30 补充）**：不改原文件里的已有代码，而是**新增**一个采样器类（暂名 `FastAncestralSampler`）和对应的配置文件，用配置切换新旧版本。原版保留，用于 D1 复现、等价性验证和回退。

### D11 RL 算法与奖励（已定，R31：GRPO + DAPO 技巧）

> **R36 补充（格式分）**：你认为格式分需要。数据：冒烟第 1 步 256 条 rollout 里能跑但错 39%、运行时错误 39%；32 题里 44% 组内全错，二值奖励下整组无信号，而这些组内都同时有能跑和报错的答案。做成开关 `--format_reward ε`（主线默认 0）：答对 1，"能跑且返回 / 打印出数字但答错"得 ε=0.1，其余 0。**必须配合 `--no_std`**：全错组里 4 条能跑、4 条报错时，除以组内标准差后优势是 ±1.0，和"4 对 4 错"组一样大，ε 失去意义；去掉 std 后格式信号约为正确性的十分之一。否决的选项：ε=0.2（"能跑但算错"漂移风险更大）、保留 std 归一化（理由同上）、直接改主线（没有数据前不换）。判分分类器 `rl/reward.py` 在 4000 条评测输出上与上游判分 0 处不一致。
>
> **R31 定下**：GRPO + DAPO 技巧，奖励 = 执行正确 1 / 否则 0。不做离线 DPO 对照（其余 DAPO 技巧、Dr. GRPO 消融、格式分等仍按下面的设计作为可选项）。
>
> **推荐理由**（提问时给出的，供面试讲）：
> 1. **奖励可验证**：执行代码判对错，0/1 奖励，不需要奖励模型——这是这道题选 RL 的根本理由。
> 2. **必须按题给基线**：GSM8K 题目难度差异极大。用全批平均分做基线时，简单题做对（常见）拿 +0.5 大力强化本来就会的，难题做错（常见）拿 −0.5 大量压低；按题基线下这两类几乎不动，信号集中在"简单题偶尔错、难题偶尔对"这种意外结果上（03 §7.2 的表）。
> 3. **GRPO 的基线来得便宜**：同一题采 G 个答案取平均。170M 模型采样便宜；G=8、每题准确率 18% 时约 80% 的题组内有对有错，信号充足（03 §7.3）。
> 4. **不做带 critic 的 PPO**：多一个价值网络、一套超参和预热；奖励只在最后给、只有 0/1，"写了一半的画布最后能拿多少分"很难学准；一周时间不划算。

> 各常规算法（PPO / DPO / GRPO / DAPO / RLOO）在 MDLM 上的可行性分析见 [03-RL算法与模型.md](03-RL算法与模型.md) §4。为什么选 GRPO 见同一文档 §7：实际选的是"组内基线、无价值网络、在线采样"这一类方法，GRPO / RLOO / Dr. GRPO 的差别做成开关。

| 项 | 设计 |
|---|---|
| 算法 | GRPO，组大小 8–16，带 DAPO 技巧：clip-higher、动态采样、token 级 loss；标准差归一化作消融（Dr. GRPO） |
| 奖励 | 执行正确 = 1，否则 0；格式分作消融 |
| 更新方式 | 先 on-policy 单次更新；稳定后再考虑 PPO clip、多 epoch |
| 题目筛选 | 丢掉组内全对或全错的题 |
| 正则 | 初期不加 KL，监控熵；出现熵崩塌再加 |
| 超参 | 学习率等在 D4 小规模 debug 时定 |
| 可选对照 | 离线 DPO：用 RFT 的"一对一错"构造偏好对；注意 log π 在 sigmoid 里，抽步估计会让 loss 有偏 |
| 不做 | 带 critic 的 PPO：要多训一个价值网络，奖励稀疏，GRPO 的组内基线已经够用 |

详见分析 §3.3。


**否决的选项及理由（R33 补；前三个是 R31 提问时的选项，后三个是 03 文档里比较过的算法）**

| 选项 | 为什么不选 |
|---|---|
| 先 RFT，再考虑 GRPO | RFT 只拿做对的样本再做一次 SFT，本质还是模仿：不会压低错误答案。R32 的诊断刚表明模仿学到的是写法、不是做对题，所以不把它放在主线第一步。它保留为止损退路（D17 草案：D5 晚 GRPO 在 dev 上仍无提升，就改用多轮 RFT 交付） |
| 朴素 GRPO（不带 DAPO 技巧） | DAPO 的技巧都是几行代码的开关，成本很低：动态采样直接省掉全对 / 全错组的计算（这些组的优势全为 0，不产生梯度）；token 级 loss 避免长回答里的每个 token 被稀释。**如实说明**：开始阶段每批只更新一次，比率恒为 1，clip-higher 在这个阶段不起作用，只有同一批更新多次时才生效；所以初期"朴素 vs DAPO"的差别主要来自动态采样和 loss 归一化 |
| GRPO + 离线 DPO 对照 | DPO 的 loss 把 log π 放在 sigmoid 里，抽轮估计会让 loss 有偏，要无偏就得每对样本算满全部 K 轮，约多 2–4 卡时；而且它是离线的，不探索新答案。同样的预算，你选了花在 D12 的 ELBO 对照上 |
| 全局基线的 REINFORCE | GSM8K 难度差异大，全局基线会大力强化本来就会的简单题、大量压低本来就不会的难题，信号错位（03 §7.2 的表） |
| 带 critic 的 PPO | 多一个价值网络、一套超参和预热；奖励只在最后给、只有 0/1，"写了一半的画布最后值多少分"很难学准（03 §4.3） |
| ReMax（用 greedy 解码的得分作基线） | 单个样本当基线，噪声大；扩散模型的"greedy 解码"揭开顺序仍是随机的，基线本身也不稳定 |

### D12 RL 的 log-prob 计算 —— 轨迹法 + ELBO 对照（已定，R31）

> **R31 定下**：主线轨迹法（分层抽 8 轮）+ 另外做一组 ELBO 近似作对照，回答"精确 vs 近似"。代价是每组约多 1.5–2 卡时。
>
> **为什么这个量是关键**：π(y|x)（最终得到这份代码的总概率）要对所有揭开顺序求和，算不出来；但策略梯度只需要 π(τ)（这一次实际发生的生成过程）的概率。轨迹法算的就是后者，是精确值，而且与评测用的解码策略一致——"训练的政策"和"评测的政策"是同一个分布。ELBO 近似便宜，但和逐步采样的分布不一致，比率和梯度都有偏差，所以只作对照、不作主线。

- **路线 B（主线）**：把采样器当作 MDP，log π = Σ（每轮新揭开位置的 log p）。这个值是精确的，与评测策略一致。每条轨迹随机抽约 8 轮带梯度重算，做无偏估计。
- **路线 A（可选对照）**：d1 式的 ELBO 代理。便宜，但只是近似。
- "精确 vs 近似"的对比可以作为一个小研究问题（分析 §2.4，讲解 §3.3）。


**否决的选项及理由（R33 补）**

| 选项 | 为什么不选 |
|---|---|
| 只用 ELBO 近似 | 便宜，但 log π 是近似值、有偏；更关键的是它对应的不是评测时实际使用的逐步采样策略，比率和梯度相对"真正被评测的那个策略"都有偏差 |
| 只用轨迹法、不加对照（R31 我的推荐） | 能省约 1.5–2 卡时；你选了加对照，因为"精确 vs 近似"能成为报告里一个有数据支撑的小研究点 |
| 每条轨迹算满全部 K 轮 | 同样无偏，但每条轨迹要 K 次（rollout 128 步时就是 128 次）带梯度前向，是抽 8 轮的 16 倍；抽轮估计已经无偏，只是方差稍大 |
| 每条轨迹只抽 1 轮 | 最便宜，但方差大；抽 8 轮时训练部分已只占 rollout 的 20–30%（03 §3 的粗算），再省收益不大 |
| 纯随机抽 8 轮（不分层） | 可能全抽到前期或后期；分层（K 轮分成 8 段、每段抽 1 轮）方差更小，实现一样简单 |

### D13 RL 起点（已定，R35：base → RL 为主线，SFT → RL 作对照）

- 原计划：主线 base → SFT → RL；时间够的话加一组 base → RL 作对照，看 SFT 对 RL 是帮助还是限制。
- **R31 讨论时的中间结果**（SFT 扫描跑到一半，20 个点里 17 个，unpaired，**未做配对检验**）：T=0.1 下 SFT 为 36.9–38.5%，与同协议 base 的 38.6% 基本持平；T=1 下 SFT 为 13.3–16.2%，低于 base 的 18.0%，幅度 2–5pp，可能显著。
  - 可能的解释（未核实）：DeepSeek 数据的风格非常统一（函数名、docstring 抄题目、变量名语义化），模型被压进这个风格后，T=1 的内在随机性破坏更大；而 6k 条 × 5 epoch 不足以学会新的推理能力。
  - 为什么影响 RL：rollout 用 T=1 保证探索；起点 T=1 准确率越低，组内"有对有错"的比例越低（G=8、p=0.14 时约 0.68，p=0.18 时约 0.80，03 §7.3 的表），学习信号变弱。
- **R35 定下**：base → RL 为主线。理由：三个 lr、全部 epoch 的 SFT 都没有好过 base（T=0.1 最好持平 38.1 vs 38.6，lr=1e-4 显著更差；T=1 全部显著更差）；RL 用 T=1 采样，起点越差组内有对有错的题越少。SFT → RL 作对照，主线跑通后再做。若 unfiltered 消融意外显著好过 base，再回头讨论。
- **R34 补充**：lr=1e-4 组在 T=0.1 下也显著变差（e2–e4：32.2–32.8% vs 38.6%，p ≤ 0.001），而它的 val loss 最低（0.049）。三个 lr 里 loss 越低、准确率越差（08 Q23）。
- **R31 的决定**：等完整结果和配对检验出来再定，不在中间数据上下结论。若 SFT 显著差于 base，改为"base → RL 为主线 + SFT → RL 作对照"，并在报告里如实写 SFT 没涨。


**否决的选项及理由（R33 补）**

| 选项 | 为什么不选 |
|---|---|
| 现在就定 SFT → RL（原计划） | 中间数据已显示 SFT 在 T=1（rollout 用的温度）下显著变差（13.7 vs 18.0，p=0.001）。起点越差，组内"有对有错"的题越少，学习信号越弱；有了这个证据，不宜直接按原计划走 |
| 现在就定 base → RL | 数据的方向支持它，但 lr=1e-4 组和 D10 消融还没出来，配对检验也没做全。SFT 在 T=0.1 下与 base 持平且语法错归零，如果 RL 后主要看 T=0.1，SFT 起点不一定吃亏。几小时后就有完整数据，不值得在半截数据上定 |

### D14 步数与温度（已定，R30：512 步 + `skip_unchanged`，T ∈ {1, 0.1}）

> **R30 定下**：你同意按 08 Q8 的规则自动定，规则是"512 步开 skip 的耗时 ≤ 256 步默认路径的约 1.5 倍就用 512 + skip，否则 256"。
>
> **实测**（`runs/1030-D2-checks-summary.md`，dev200，batch 200，T=1，只算采样时间）：
>
> | 步数 | 默认路径 | skip | skip 相对 256 默认 |
> |---|---|---|---|
> | 256 | 53 s | 44 s | 0.83 |
> | 512 | 104 s | 63 s | **1.19** |
> | 1024 | 208 s | 78 s | 1.47 |
>
> 1.19 ≤ 1.5，所以主设置用 **512 步 + skip**。Q8 估的是 1.2 倍（512）和 1.4 倍（1024），估计基本准。
>
> **为什么推荐这条规则、为什么最后是 512**：
> 1. **准确率**：dev 1000 上 512 比 256 在两个温度下都高（T=1：17.8 vs 15.6；T=0.1：38.8 vs 36.9），单看都不显著（p=0.14 等），但方向一致；1024 没有比 512 更好（17.5 / 38.1）。
> 2. **机制**：步数越多，同一步里一起揭开的答案词越少，"同一步揭开的词之间互相独立"这个近似带来的误差越小。dev 上模拟，只和自己单独揭开的答案词，256 步是 59%，512 步是 77%（见「已更正的判断」10-30 那条）。
> 3. **代价**：开 skip 后 512 只比 256 默认路径慢约 19%，dev 1000 一次评测从约 4.6 分钟变成约 5.5 分钟；1024 + skip 又贵约 25%，但没有更好，所以不用。
> 4. **留余量**：SFT / RL 后的模型对步数的敏感度可能不同，主设置用一个已在平台上的步数更稳。
> 5. 规则是在看到测速结果**之前**定的（Q8），避免看结果再挑。
>
> **注意（R30 实测，已更正 Q8 的说法）**：skip 和默认路径**同分布、但不逐位相同**。评测开了 TF32（`main.py:613`），cuBLAS 按矩阵大小选 kernel，子 batch 在 21–127 行（以及 1 行）时隐状态与整批有舍入级差异，2–20 行和 128–200 行逐位相同。256 步时每步约 160 行前向，结果完全相同；512 / 1024 步时约 110 / 66 行，dev200 上分别有 29 / 28 条输出在某处分叉，逐题对错只差 1 / 4 题。所以 SFT 扫描另跑了**同协议（512 + skip）的 base**，所有配对比较都对它做。
>
> **否决的选项及理由（R33 补）**
>
> | 选项 | 为什么不选 |
> |---|---|
> | 固定 256 步 | 规则是在测速之前定的；512 在两个温度下方向上都更好（dev 1000：17.8 / 38.8 vs 15.6 / 36.9，不显著），开 skip 后只多约 19% 的时间 |

### D20 pad 位置是否计入 log-prob（已定，R33 实现时定：计入；`count_pad=False` 留作消融）

- 生成区约一半是 PAD。它们也是"动作"，但 log-prob 接近 0。
- **做法**：PAD 和其他 token 一样算动作，计入 log π(τ)，也计入 token 级 loss 的分母（`rl/logprob.py`、`rl/grpo.py`）。
- **理由**：
  1. 扩散生成里 PAD 不是"生成结束后补的"，而是模型在某一轮主动写下的：PAD 写在哪里，就决定了答案多长。提前写 PAD 把答案截断，是真实存在的失败方式，应该能被奖励信号纠正。
  2. 策略梯度的恒等式要求 ∇ log π(τ) 包含轨迹里的**全部**动作；去掉一部分动作，求的就不是真实策略的梯度了，会有偏。
  3. 代价很小：PAD 位置大多接近确定（log p ≈ 0，梯度也小），算进去不怎么占梯度。
- **R43 实测**（`runs/1031-diag-kl-grad/`，KL 轮第 225 步，一批 rollout）：理由 3 成立。PAD 占被抽到动作的 68%，平均 log p 为 −0.002（非 PAD 为 −0.29）；PAD 部分的梯度范数只有总量的 11%，与非 PAD 部分几乎正交（余弦 −0.01）。
- **副作用（如实说明）**：计入 PAD 后，每条轨迹的动作数都等于"512 − 题目长度"，几乎一样长。所以 DAPO 的"token 级归一化"和"按样本平均"在这里差别很小，token 级 loss 这个技巧基本退化。
- **否决的选项**：

| 选项 | 为什么不选 |
|---|---|
| 不计入 PAD（只算答案词和 EOS） | 梯度有偏，而且忽略了"答案在哪里结束"这个决策；AR 模型可以不算 EOS 之后的位置，是因为那些位置根本没有生成，而 MDLM 的 PAD 是真的生成出来的 |
| 计入 log π，但不计入归一化分母 | 分母和分子口径不一致，有效学习率会随题目长度变化，没有好处 |

### D29 SFT 训练怎么接上游代码（实现时定，R27，我按默认做）

- **做法**：`code/scripts/sft.py` 用一个普通的 PyTorch 训练循环，**直接调用上游的 `MDLM._loss`**（与预训练相同的 NELBO），数据格式与预训练一致（`[BOS] 题目 SEP 代码 [EOS] [PAD]*`，`train_on_prompt=False`、`train_on_pad=True`）。不改上游任何文件。
- **R30 更正**：原来写"逐 token 对过"，但分隔符错了。上游 yaml 写的是 `separator: '\n'`（单引号，YAML 不转义），所以 SEP 是**字面量反斜杠 + n 两个字符**（token `[76, 94]`），预训练（checkpoint 里保存的配置）和 GSM8K 评测都是这样；`sft.py` 原来用的是真换行（token `[198]`）。已修复，并加断言要求 SEP 与 checkpoint 保存的配置一致。发现过程见「已更正的判断」和 06。
- **为什么不用上游的 `mode=train training.finetune_path=...`**（读代码和 checkpoint 核实）：
  1. `load_from_checkpoint` 恢复的是**训练权重**，但所有评测（包括我们测的 base）用的是 **EMA 权重**。发布的 checkpoint 里两者相对 L2 差约 10%（mmap 加载实测）。SFT 会从一个没测过的模型出发。
  2. 恢复的 EMA 衰减是 0.9999、`num_updates`=250k。几百步 SFT 后，被评测的 EMA 权重只会移动百分之几，等于 SFT 几乎没生效。
  3. Lightning 还会恢复预训练的 dataloader 进度和 2500 步 warmup。
- **因此**：从 EMA 权重出发，SFT 期间不用 EMA；保存的 checkpoint 让 `state_dict` 和 `ema.shadow_params` 指向同一组张量，评测脚本可以直接加载。
- **冒烟测试**（`code/scripts/smoke_sft.sh`）：lr=0 跑 20 步，dev200 准确率必须和 base 在同一 seed 下完全一样（验证"从 EMA 出发 + 保存格式"没错）；lr=1e-4 跑 20 步，loss 必须下降。
- **超参默认值**（需要学习率扫描定）：AdamW，weight decay 0、梯度裁剪 1.0（与上游相同）；batch 64；5 epoch；5% warmup + cosine 降到 10%。理由见 D30。

| 每批更新次数 | 4（旧 log-prob 每批先算一次，4 次更新共用同一批抽到的 8 轮；比率 clip 到 [0.8, 1.28]） | rollout 占每步约 90% 时间，多更新 3 次只多约 12 秒，学习量是单次的数倍；多次更新时 clip 才生效，给每批改动设上限。4 是 PPO 常用的 2–4 次的上端：更多次时样本越来越"旧"、clip 大量饱和 |
| 每步 | 32 题 × G=8，rollout 128 步 T=1 | 同 D31 |
| 步数 | 300（约 1.5 遍 6312 题的题库） | 原计划 D5 的步数；你选的 |
| 评测 | 每 25 步 dev200，512 步 + skip，T ∈ {1, 0.1} | 与 base 同协议、可配对；dev200 标准误约 3pp，只看趋势 |
| 选 checkpoint | 每臂取 dev200 两温度平均最高的那步（平手取较早的），再在 dev1000 上评测两个温度；报告 dev1000 全集和**后 800 题**（选择时没用过，无选择偏差） | 规则事先定死；dev200 是 dev1000 的前 200 题，直接报 dev1000 会因选择而偏乐观 |
| 关机 | 两臂跑完、汇总推送后关机（有 `/root/autodl-tmp/NO_SHUTDOWN` 则不关） | 你的要求 |
| 时间（估计） | 每步约 50 秒；每臂约 4.7 小时（含评测）；共约 10 小时 | — |

**否决的选项及理由**

| 选项 | 为什么不选 |
|---|---|
| lr 3e-5，单次更新 | 300 步权重变化约 0.4%（估计），可能不够看出提升；每批 rollout 只用一次，浪费了占 90% 时间的采样 |
| lr 1e-4，单次更新 | 学得最快，但 300 步约 1.3%，在 SFT 会把模型训坏的量级；单次更新时比率恒为 1，clip 不起作用，没有保护 |
| 先各跑 30 步小探针再定 | 多约 40 分钟；固定 8 题 30 步的奖励在 1e-4 下都分不清趋势，30 步探针多半仍分不出 |
| 只跑一臂（二值或格式分） | 没有对照，说不清涨分是不是格式分带来的 |
| 200 / 100 步 | 你选了 300；200 步也够看效果，100 步可能不够 |
| 每批 8 次更新 | 样本更"旧"，clip 大量饱和，收益递减 |

### D33 D5 二值臂发散后怎么继续（已定，R39）

> **R39 定下**：停掉原流水线；格式分臂加自动刹车重跑（其余配置与二值臂完全相同），最多 150 步；两臂按 D32 的规则选 checkpoint 上 dev1000。约 3.2 小时，跑完关机。

**现象**：见 06「D5 正式 RL 结果」和 08 Q32。二值臂前约 150 步有效（训练正确率 0.145 → 0.25，dev T=1 第 100 步 +8pp，p=0.033），之后被揭开 token 的 log-prob 从约 −0.07 掉到 −1.8，输出变成乱码。

| 项 | 取值 | 理由 |
|---|---|---|
| 刹车 | 最近 10 步平均 action log-prob < 2 × 前 10 步平均，就在这一步存 checkpoint、评测并停止 | 用相对阈值：格式分臂保留的轨迹更多样，log-prob 起点更低（调试时约 −0.11 vs 二值 −0.087），固定阈值会让它过早触发。拿二值臂的日志回放，会在第 160 步停（阈值 −0.174），正好在开始崩的地方 |
| 步数上限 | 150 | 二值臂健康的区间约到 150 步；两臂在同样的步数预算内比较。刹车是兜底 |
| 其他 | 与二值臂完全相同（lr 3e-5、每批 4 次更新、去 std、同 seed 同题序） | 只差奖励一个变量；二值臂第 1–150 步的数据可以直接对照 |
| 选 checkpoint | 二值臂按规则选第 150 步（dev200 两温度平均 36.25，第 100 步 34.75）；格式分臂同规则 | 规则事先定的，不因为看到发散而改 |

**否决的选项及理由**

| 选项 | 为什么不选 |
|---|---|
| 照原计划跑完（格式分臂同配置 300 步） | 多半在 150 步左右崩，后一半约 2.5 小时 GPU 浪费；"只保留最好的 checkpoint"能保住结果，但没必要付这笔时间 |
| 全停，白天再定 | 今晚 GPU 空着；格式分臂只加刹车、不改其他配置，不需要新的设计决策 |
| 格式分臂同时加 KL 或降学习率 | 会多出一个变量，没法和二值臂对比；防发散的改法（KL、降 lr、减少每批更新次数）留到白天单独讨论 |
| 固定阈值刹车（−0.15） | 两臂 log-prob 起点不同，固定阈值对格式分臂更严 |

### D35 收敛轮与新的选点规则（已定，R44）

> **R44 定下**：① 跑一轮"真能收敛"的 RL，选**最后一步**；② 以后探索性的实验，选 checkpoint 改用"dev200 两温度平均的三点平滑最高，平手取更晚"；③ 第 100 步不作定稿。

**为什么要改**（你的判断成立，核实结果）：
- **第 100 步是单点噪声**：格式分臂 dev200 两温度平均第 75/100/125/150 步为 0.37 / **0.41** / 0.39 / 0.39。第 100 步两侧都低 2 个点，而单点标准误约 2.5–3 个点。
- **同一条规则在二值臂上挑中了漂移边缘**：第 150 步（平均 0.36）的 log-prob 已从 −0.067 掉到 −0.094，下一步起加速发散。
- **训练没有收敛**：健康期内训练正确率只从 0.272（第 76–100 步）爬到 0.282（第 126–150 步）；dev200 在 75–150 步之间平而散。常数学习率、无锚定的 GRPO 在这里不是"训到收敛"，而是"训到发散"——二值第 160 步、SFT → RL 第 138 步、格式分第 174 步都被刹车停住。唯一跑满 300 步的 KL 轮 dev200 在 0.30–0.37 间平而无趋势，也没有收敛。

| 项 | 取值 | 理由 |
|---|---|---|
| 起点 / 奖励 | base，格式分 0.1，去 std（与 D32/D33 同） | 保持与已有各臂只差正则和调度，方便按步配对 |
| KL | β=0.04，k3 截断：`--kl_clip 20 --kl_max 10` | 第一次 KL 轮第 14 步梯度范数约 2500（常态 0.016），尖峰来自 exp(d) 无界；20 / 10 是 verl `low_var_kl` 的上限 |
| 尖峰跳过 | `--spike_ratio 10`：某次更新的梯度范数超过最近 50 次中位数的 10 倍，就丢弃这次更新 | 被裁剪的尖峰会写进 Adam 的二阶矩，压小之后很长一段有效步长（09 §2.1 的推测）。跳过比裁剪干净 |
| 学习率 | `--lr_schedule cosine --lr_min_frac 0.1`，3e-5 → 3e-6 | 让步长在末段变小、结果安定；这是"收敛"成立的前提之一 |
| 步数 | 400 | 按前几轮的发散速度约 175 步算，加 KL 和调度后应有足够余量训到平台 |
| 定稿 | **最后一步**（`--keep_ckpts last`） | 收敛轮不需要在一堆 checkpoint 里挑；摘要里另打印 smooth3 会选哪一步，仅作透明性检查，不用于定稿 |
| 选点规则（以后） | dev200 两温度平均的三点平滑最高，平手取更晚 | 避开单点噪声；平手取更晚偏向训练量更大的点 |
| 时间 | 约 9–9.5 小时（400 步 × 约 82 秒 + dev1000 两次） | 估计；先跑 2 步正式参数冒烟（脚本内置） |

**否决的选项及理由**

| 选项 | 为什么不选 |
|---|---|
| 保持第 100 步定稿 | 它是单点尖峰，且训练远未收敛；报告里会被问"为什么停在崩之前一步" |
| 只改选点规则、不训练 | 已有的 checkpoint 里，健康期内"更晚"的点只有格式分第 150 步（125 步已删），它也已进入漂移（log-prob −0.084、语法错 1.5%）。能省 9 小时，但拿不到一个"训练到平台"的模型 |
| 不用 KL，只加 cosine 衰减 | 前四轮说明发散不是只由步长造成（二值臂 lr 恒定、clip 只有 1–2% 也崩）；没有锚定时衰减只是推迟发散 |
| 400 步更长（600+） | 时间够，但收益未知；先用 400 步验证"能训到平台" |

### D34 D5 第三轮跑什么；定稿模型怎么选（已定，R43）

> **R43 定下**：今晚依次跑 ① SFT（lr 1e-5，epoch 1）→ RL，格式分配置，150 步；② base → RL 格式分臂，带刹车跑满 300 步。跑完汇总、推送后关机。定稿模型 = 到 D6 时所有候选里 dev1000 两温度平均最高者，平手取更简单的配置。

**背景**：三臂（二值第 150 步 / 格式分第 100 步 / 格式分 + KL 第 225 步）在 dev1000 上两两都不显著；KL 轮被第 14 步的梯度尖峰混淆（09 §2.1）；格式分臂截在 150 步，"会不会崩"没有答案（08 Q42）。

| 项 | 取值 | 理由 |
|---|---|---|
| ① SFT → RL | `--init_ckpt sft_ckpt/1030-sft-v1b-lr1e-5/epoch1.ckpt`，格式分 0.1、去 std、lr 3e-5、每批 4 次更新、刹车、150 步 | D13 已定的对照（题目要的 base → SFT → RL）。与 base 出发的格式分臂只差起点，可以按步配对 |
| SFT 起点用 epoch 1 | — | 按 D30 规则，两温度平均最高（27.0；epoch 2–5 为 25.4–26.4）；T=1 下与 base 无显著差别（16.2 vs 18.0，p=0.095），epoch 5 显著更差（14.7，p=0.007）；RL 在 T=1 下采样，起点越好、有对有错的组越多（08 Q44） |
| ② 格式分臂 300 步 | 与 D5 格式分臂相同，上限改为 300 | 先回答"只用格式分会不会崩"：它是"KL 有没有用"必需的对照（不加 KL 会崩，KL 防崩才有意义）。不改代码。前 150 步顺带重复一次原格式分臂（同 seed，GPU 不逐位确定），给出跑与跑之间差异的一个样本 |
| 定稿规则 | D6 时在所有候选（含 ①②）里取 dev1000 两温度平均最高；平手取更简单的配置 | 与 D32 / D33 一贯的规则一致；先定规则再看结果，避免挑樱桃。跨臂挑选会用到后 800 题，报告注明只有 test 是干净的（09 §4.2） |
| 关机 | 跑完、汇总、推送后关机 | 你的要求 |

**否决的选项及理由**

| 选项 | 为什么不选 |
|---|---|
| 第二项换成修好的 KL | 没有"不加 KL 跑 300 步"的对照，就算不崩也说不清是 KL 的功劳（又回到 Q42 的局面）；要新写截断 / 跳过逻辑，夜里跑刚改的训练循环风险更高（Q34）。格式分 300 步若崩了，明天再跑修好的 KL |
| 只跑 SFT → RL | 夜里 GPU 闲置约 6 小时 |
| ELBO 对照（D12） | 要先写 ELBO log-prob 并冒烟（约 1–1.5 小时），今晚来不及；仍在待做清单 |
| SFT 起点用 epoch 5（"完整 SFT"） | T=1 显著差于 base，RL 从更差的起点出发；按 dev 选 epoch 是标准的早停 |
| 现在就定格式分第 100 步 / 二值第 150 步 | 三者在 dev 上不可分辨；事先定"按 dev 平均选"的规则同样避免了挑樱桃，又不排除今晚可能更好的新候选 |
